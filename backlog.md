## [C] Critical / crash

- [2026-08-15] [C] settings-file.js:55-57's `run.finally(() => {...})` returns a derived promise that also rejects when `run` rejects, and nothing catches it; Node's default unhandled-rejection handling kills the process. Any settings write failure (read-only .claude/ dir, full disk, flaky network share) triggered via server.js:307/349/360 takes down every live session, not just the one request. Fix: `.finally(...).catch(() => {})` or move cleanup into the `.then` chain.

Separately, do not attribute plain idle-gap expiry (the default cache TTL is 5 minutes, refreshed on every read) to a user action - a warning that cries wolf after a coffee break is worse than none.
